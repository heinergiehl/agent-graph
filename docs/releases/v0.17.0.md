# AgentGraph v0.17.0

This release unifies synchronous and queued execution around durable node receipts. Laravel AI remains responsible for agents, providers, messages, native tools and the model loop; AgentGraph supplies graph execution, checkpoints and controlled continuation.

## Changes

- Both execution modes persist the complete frontier before invoking nodes, claim individual Send instances and reuse completed receipts on recovery. The separate synchronous execution loop was removed.
- Run transitions use an expected revision. A late worker cannot overwrite cancellation or commit a checkpoint under an obsolete revision. Cancellation no longer waits for the cache lock held by a running node. Concurrent control requests may receive `RunStateChangedException`; reload the authoritative run before deciding whether to retry.
- Admission is checked before each invocation, after concurrency-lock waiting, and before every retry. Subgraph nodes check ancestor cancellation. Nodes can call `NodeContext::assertActive()` before another external operation and inspect `remainingSeconds()`. A node timeout covers retries and backoff; `AgentNode` bounds its provider timeout by the remaining budget.
- The in-memory testing driver rolls back its checkpoint, write, interrupt, run and execution mutations when a runtime transaction fails.
- Diagnostic event listeners, trace sinks and text-delta callbacks cannot turn confirmed execution into failure. Persisted receipts and queue dispatch failures remain consequential. Listeners are not authorization hooks.
- `AgentNode` consumes Laravel AI's completed stream response for text, usage, metadata and tool results. It records one bounded `stream.completed` trace instead of writing every delta to the database. Requesting structured output or step mapping in stream mode fails before the provider call because Laravel AI 0.11.2 does not populate those final stream fields.
- Declared interrupt-capable nodes in a parallel frontier are rejected before sibling execution. Dynamic undeclared parallel interrupts remain unsupported and fail when encountered.

## Upgrade

Stop workers and requests that execute graphs during deployment. Update the package, publish migrations, migrate, run the doctor, then restart all processes on the same dependency set:

```bash
composer require heiner/agent-graph:^0.17.0 --with-all-dependencies
php artisan vendor:publish --tag=agent-graph-migrations
php artisan migrate --force
php artisan agent-graph:doctor
```

The additive migration introduces `agent_graph_runs.revision` with default zero. Existing identities, waits, deadlines and receipts remain intact. The revision column intentionally survives rollback. Custom `RunStore` implementations must implement `transition(string $runId, int $revision, array $attributes): array` atomically, increment the revision and throw `RunStateChangedException` on a mismatch. Custom fault-injection or persistence decorators must intercept this method rather than only `update`.

Synchronous execution now requires the node-execution table and retains node receipts. Apply the existing retention policy to these additional records. An old in-flight frontier without receipts cannot gain retrospective crash protection.

The chatbot plugin currently pins an exact SDK version. Its next integration change must pin `0.17.0`, update its Composer lock and pass its own runtime gates; `composer update` alone cannot override that pin. This release does not modify or approve the plugin runtime.

## Guarantees and limits

Cancellation revokes permission for new SDK-admitted work and prevents stale commits. PHP cannot forcibly interrupt arbitrary blocking user code or undo an external request already admitted. Custom nodes and application tools must check cancellation before subsequent operations and configure network timeouts. Laravel AI's inner multi-tool loop is not independently checkpointed by AgentGraph; the application's capability gateway must enforce authorization, idempotency and reconciliation at each tool boundary.

A process can die after an external effect but before saving its receipt. Such an effect still needs an operation ID and provider reconciliation; this release does not claim exactly-once external execution. An active node lease must expire before a replacement worker can claim it. In-memory persistence is process-local and does not provide crash recovery.

Native Laravel tool approval resumption remains explicitly unsupported by `AgentNode`, as in 0.16.3. Generic graph-tool adapters remain trusted application integration surfaces: the host must bind users/tenants, filter public inputs and outputs, and authorize status, resume and cancel. They are not safe as unauthenticated public endpoints. No new provider stack, chatbot policy engine or authorization framework is introduced.
