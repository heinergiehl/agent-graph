# AgentGraph v0.16.1

Status: **Stable pre-v1 patch release**. Release date: 2026-09-02.

AgentGraph 0.16.1 fixes a deployment-blocking migration edge case in 0.16.0. It changes no graph runtime behavior, public runtime signature, dependency constraint, or migration filename.

## Incident and fix

Laravel can timestamp a migration when publishing it into a host application. A previously recorded RC or published timestamp variant could therefore create `agent_graph_node_executions.claim_token` before the canonical package migration name ran. On PostgreSQL, the still-pending 0.16.0 package migration then attempted another `ADD COLUMN` and failed with SQLSTATE `42701` (`Duplicate column`).

The existing migration now inspects the configured AgentGraph connection and node-execution table before issuing DDL:

- a missing column is created as nullable `varchar(26)` and the resulting definition is verified;
- an existing nullable `varchar(26)` with no default, auto-increment, or generated behavior is accepted without rewriting rows or issuing `ADD COLUMN`;
- an incompatible type, length, nullability, default, auto-increment, or generated definition throws a descriptive exception before mutation; and
- a missing node-execution table also fails explicitly instead of hiding an incomplete base migration.

SQLite does not retain declared `varchar` lengths in schema metadata, so its logical `varchar` type and nullability are validated. PostgreSQL, MySQL/MariaDB, and SQL Server retain and validate the exact length.

Rollback validates the observed schema before removal. It no-ops for an absent table or column, preserves a compatible column when another recorded timestamp variant of the same migration owns it, and still removes a column created by a fresh standalone run. It never coerces an incompatible definition during rollback.

## Upgrade

General applications should install the patch and update their lock before rerunning migrations:

```bash
composer require heiner/agent-graph:^0.16.1 --with-all-dependencies
php artisan migrate --force
```

Keep application and queue execution stopped until the migration and `php artisan agent-graph:doctor` succeed. Do not delete migration records, drop the existing column, or force-overwrite application-owned migrations merely to bypass the compatibility check. If an application copied the old migration into its own `database/migrations` directory, Composer will not rewrite that application-owned file; reconcile it through the application's normal reviewed migration process.

Applications whose 0.16.0 claim-token migration was already recorded successfully need no schema change. The Filament Agentic Chatbot release must pin exact `0.16.1` in its package and release contract, refresh its lock, and pass its own release gates.
