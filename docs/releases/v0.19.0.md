# AgentGraph 0.19.0

This minor release moves AgentGraph to Laravel AI 1.x and makes the database schema install and behave the same on MySQL 8.4 and MariaDB 11.4 as on PostgreSQL and SQLite. It is a minor rather than a patch release because it drops Laravel AI 0.11, changes the `AgentNode` usage channel shape, adds a migration and tightens memory identity validation.

## Changes

- **Laravel AI `^1.2.1`.** Laravel AI 0.11 is no longer supported; the test fixtures implement the 1.x `Agent` contract (`AgentInput|UserMessage|Decisions|string $prompt`). Supporting both lines would require two incompatible fixture sets for the same contract. `AgentNode::writeUsageTo()` stores `TextUsage::toArray()`: `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_write_input_tokens`, `reasoning_tokens`. Laravel AI 1.x counts cached input inside `input_tokens` and reasoning inside `output_tokens`.
- **MySQL 8.4.** The composite memory unique index on five `varchar(255)` columns needed 5,100 bytes with utf8mb4 and failed with error 1071 (limit 3,072). The create migration now declares scope type 64, scope id 191, tenant id 128, namespace 128 and key 255 characters (3,064 bytes).
- **MariaDB 11.4.** MariaDB reports a nullable column without a default as the expression `NULL`, which the claim-token migration rejected on every fresh installation. The compatibility check now accepts that expression on the `mysql` and `mariadb` drivers only; a quoted string default stays incompatible.
- **Memory identity limits.** `MemoryIdentity` defines the limits above. `DatabaseMemoryStore` and `InMemoryMemoryStore` reject longer parts with `InvalidArgumentException`, so code tested against the in-memory store fails the same way it would on MySQL.
- **Unique identity for records without a tenant.** SQL unique indexes treat NULLs as distinct, so concurrent writes could create two records for the same identity when the tenant was null. The new migration `2026_10_14_000000_add_identity_hash_to_agent_graph_memories` adds a unique SHA-256 `identity_hash`, backfills existing records (for legacy duplicates only the oldest gets the hash; nothing is deleted) and is idempotent. A lost concurrent insert race now updates the winning record inside a savepoint instead of surfacing a unique-constraint error. `agent-graph:doctor` fails while the column is missing.

No runtime, checkpoint, resume, run or task persistence format and no public graph API changes.

## Upgrade

See [UPGRADE.md](../../UPGRADE.md#0181-to-0190-laravel-ai-1x-and-portable-mysqlmariadb-schema). In short: update `heiner/agent-graph` and `laravel/ai` in one lock operation, stop workers, publish and run the new migration, run `agent-graph:doctor`, restart all processes. Applications that published earlier AgentGraph migrations and now install on a fresh MySQL database must republish the create migration first.

## Verification

- Local PHP 8.4.4, Laravel 13.36.0, Laravel AI 1.2.1: `composer check` (Pint, Pest, PHPStan, production audit) passed; Pest **493 passed, 7 skipped** (the skips are the opt-in database tests below).
- `tests/Integration/DatabaseSchemaPortabilityTest.php` runs every migration on a disposable database and exercises the claim token and memory identity contracts: passed on MySQL 8.4, MariaDB 11.4 and PostgreSQL 15 (pgvector image). Before the fix the same test failed on MySQL with error 1071 and on MariaDB with the incompatible claim-token default.
- The PostgreSQL opt-in suites (runtime concurrency, claim-token migration, pgvector memory store) passed on PostgreSQL 15.
- CI adds MySQL 8.4 and MariaDB 11.4 jobs and runs the portability test in the PostgreSQL 17 job.
- The consuming Filament Agentic Chatbot ran its memory-related suites (322 tests) against this candidate before release.

## Limits

The memory limits are validation, not truncation: callers must hash longer identifiers. Existing records whose parts exceed the new limits (possible only on PostgreSQL or SQLite) can still be read, exported and deleted but no longer written under the same identity. No paid provider calls were made.
