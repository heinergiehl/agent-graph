# AgentGraph v0.16.0 preparation

Status: **Unreleased**. Audit and local verification date: 2026-08-31.

This refactor starts from v0.15.1, commit `1774548b448e11b7d03a0fc9e424f60a5f51a9c9`. It hardens durable ownership, wait transitions, recovery, and Laravel AI/subgraph boundaries. It does not replace Laravel AI, introduce a second runtime, or claim that arbitrary external effects execute exactly once.

The development branch is `codex/agentgraph-runtime-hardening`; the Composer `dev-main` alias is prepared for `0.16-dev`. No tag, package release, deployment, or consuming-plugin dependency update is part of this change. The README keeps the published `^0.15.1` installation command until release.

## Audit findings and fixes

| Audit finding | Previous failure | Implemented behavior |
| --- | --- | --- |
| AG-01: wait persistence | A checkpoint observer could fail after committing the checkpoint but before storing the approval interrupt. Recovery could follow a successor without approval. | Sync and queued paths share one database transaction for checkpoint, writes, wait interrupt, and waiting status. Observers run afterwards. Wait schedules point back to the waiting node. |
| AG-02: task acquisition | A find-then-start race allowed duplicate ownership of one task key. | `start()` claims atomically, rejects active leases and conflicting input, and returns completed receipts unchanged. Final writes require the matching running attempt. |
| AG-03: completion observers | A throwing task-completed observer could downgrade a completed receipt to failed, enabling another external call. | Completion persistence and observation are outside the handler-failure catch. The observer can still fail the caller, but the receipt stays completed. |
| AG-04: lineage queries | Filtering after a global 1,000-row limit hid matching children behind unrelated recent runs. | Database queries filter parent/checkpoint lineage before applying the requested limit. PostgreSQL queries cast the shipped text metadata column to JSONB. |
| AG-05: tool/session scope | An explicit run ID could resume a different graph or thread. | `GraphTool` checks graph and any configured/supplied thread. `DurableGraphSession` always checks graph and thread before resume. Host authentication remains required. |
| AG-06: child identity | Caller-supplied child IDs could target another run or a newer child interrupt after an old parent prompt. | Stored parent/child lineage and exact interrupt IDs are validated before parent acceptance, including nested children and accepted-response recovery. |
| AG-07: delayed children | A delayed child could be mapped as successful output and let its parent proceed. | Delayed children produce a parent waitpoint. Only completed children produce output; failed, cancelled, or still-running children do not complete the parent. |
| AG-08: streamed errors | A terminal public Laravel AI `Error` event could leave partial text treated as success. | Non-recoverable errors throw `AgentStreamException` and follow node failure/retry handling. Recoverable errors may continue to a valid response. |
| AG-09: continuation dispatch | A failed queue push after node completion could replace the successful execution with a failure. | Node outcomes remain durable. Dispatch errors propagate for retry without changing the completed execution. |
| AG-10: initial queue recovery | A lost initial dispatch left durable node records but no checkpoint, and recovery refused to continue. | Recovery can redispatch the persisted first frontier before any checkpoint exists. It still rejects runs with neither checkpoint nor durable frontier. |
| AG-11: cancellation races | A late worker failure could overwrite a cancelled run. | Run failure re-reads authority under the run lock and preserves terminal status. |
| AG-12: embedded definitions | A parent containing an inline child definition could start the child but fail to find it on resume or after restart. | Defining the parent recursively registers embedded child definitions. Conflicting keys are rejected before partially changing the registry. |

The implementation also closes three related failure cases found while reproducing these boundaries:

- Queued node completion, interruption, and failure require the original claim token. An expired worker cannot overwrite a replacement worker's result. `NodeExecutionClaimLostException` leaves the winning record and run intact.
- A persisted failed peer takes priority over pending peers during dispatch, execution, and aggregation. A crash between recording the peer failure and failing the run no longer starts additional pending peer work on recovery.
- Invalid child state is checked recursively before accepting any parent response. A rejected response leaves the parent and nested waits available for a corrected answer.

Recovery also refuses ambiguous legacy wait schedules unless stored interrupt and execution records prove the matching response was accepted. This guard applies to recovery, already-dispatched node jobs, and completed-frontier aggregation. Legitimate old approval/state-edit resumes and distinct `Send` inputs targeting the same node remain supported.

## Breaking changes

This is a minor pre-v1 version change, not an automatic `0.15.x` patch upgrade. See the exact signatures and rollout steps in [UPGRADE.md](../../UPGRADE.md).

1. `TaskStore::complete()` and `fail()` require the claimed integer attempt as their second argument. Implementations must claim and finish atomically.
2. `NodeExecutionStore::complete()`, `interrupt()`, and `fail()` require the claimed string token as their second argument. Update overrides and decorators as well as interface implementations.
3. Apply `2026_08_31_010000_add_claim_token_to_agent_graph_node_executions.php`. It adds nullable `claim_token` without rewriting old rows. Existing completed records remain readable; pending work receives a token on claim, and legacy running work must become reclaimable after its lease. Task attempts require no migration. `agent-graph:doctor` detects a missing node-token column.
4. Review protected extension points: `GraphRuntime::persistQueuedInterrupt()` and `DatabaseTaskStore::isDuplicateKeyException()` were removed; both node stores' `updateResult()` signature now includes the token. Runtime persistence and notification are separated into `persistSuperstepCheckpoint()` and `notifySuperstepCommitted()`.
5. Graph/thread/subgraph scope checks reject previously accepted invalid requests. A `GraphTool::thread()` resolver now runs on resume too. Top-level child identity fields are reserved for subgraph resumes. Child schema errors occur before parent acceptance.
6. Terminal stream errors now fail the node instead of committing partial output. Consumers must distinguish displayed deltas from a successful final result.

Public graph-building, run/resume, and `TaskRunner::once()` signatures remain unchanged. These runtime APIs still require application authorization and correct graph/version registration. Checkpoint payloads retain existing fields; the new wait metadata is additive. Compatible persisted v0.15.1 subgraph waits were tested without rewriting their payloads.

## Plugin handoff and remaining gates

The [Filament plugin upgrade guide](../guides/filament-plugin-upgrade-0.16.md) includes a portable patch for the two required bounded-store overrides. The SDK and those plugin changes must be deployed together after draining all old web, Octane, Horizon, queue, and scheduler execution. Preserve deployment artifacts and pinned graph versions for existing runs.

**A separate existing plugin recovery defect remains open.** If a process fails just after a parent subgraph response is accepted, `StructuredConcurrencyGraphRuntime` can reject the duplicate accepted response or lose authorized child-resume context during `recover()`. Temporary fault tests reproduced both behaviors on SDK 0.15.1 and this SDK build (two tests, 22 assertions per build). They characterize the defect; they do not prove successful recovery. The two-store patch does not fix it. The plugin release needs a bounded recovery fix preserving its authorization, lineage, current-interrupt, cancellation, and locking rules. Keep the structured-concurrency wrappers.

The following gates were **skipped**, not passed: live model/provider calls, real PostgreSQL/MySQL integration and concurrency, pgvector integration, the full PHP/Laravel/dependency matrix, the complete plugin suite, external host-app smoke tests, and an actual release deployment. PostgreSQL lineage SQL was compile-checked only. Those environments must be verified before making the corresponding support or joint-release claim.

Known boundaries remain explicit: a remote effect can succeed before its receipt is stored; expired leases cannot cancel work already in flight; `recover()` does not redeliver a pending delay whose queue push was lost; synchronous work before a checkpoint can execute again; SDK parent cancellation does not cascade by itself; asynchronous subgraph orchestration is not added. Use stable operation identities, provider idempotency, and reconciliation where required. This refactor fixes demonstrated SDK failures without promising universal fault-free execution.
