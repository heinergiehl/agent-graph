# AgentGraph v0.16.0

Status: **Stable pre-v1 release**. Promotion date: 2026-09-02.

AgentGraph 0.16.0 promotes the runtime released and verified as `v0.16.0-rc.2` at commit `43c570e82ab599b6dec924858160f86ac9e70220`. The stable-promotion slice changes release documentation only; it adds no runtime code, public signature, dependency constraint, or migration beyond RC2.

Install the stable line with:

```bash
composer require heiner/agent-graph:^0.16.0 --with-all-dependencies
```

Existing `^0.15.1` applications do not receive this minor release automatically. Complete the [upgrade guide](../../UPGRADE.md) before changing the constraint.

## Stable scope

The stable line contains the complete RC1 durability hardening and RC2 pending-delay redelivery:

- task attempts and queued-node claim tokens fence stale final writes;
- database-backed checkpoints, writes, interrupts, and waiting status commit atomically before observation;
- recovery handles accepted resume transitions, durable queued frontiers, and valid committed delays without inventing authority;
- graph, thread, checkpoint, interrupt, child-run, and embedded-definition boundaries reject stale or foreign resumes;
- terminal Laravel AI stream errors fail the node instead of turning partial text into a successful result; and
- a valid pending delay can be scheduled again with the same interrupt identity and original absolute due time.

The detailed audit and prerelease evidence remain available as [RC1](v0.16.0-rc.1.md) and [RC2](v0.16.0-rc.2.md) history.

## Breaking upgrade requirements

This is a minor pre-v1 upgrade, not a patch update from 0.15.1.

1. Adapt every `TaskStore` implementation and caller to pass the claimed integer attempt to `complete()` and `fail()`.
2. Adapt every `NodeExecutionStore` implementation and caller to pass the claimed string token to `complete()`, `interrupt()`, and `fail()`.
3. Publish and run `2026_08_31_010000_add_claim_token_to_agent_graph_node_executions.php` on the configured AgentGraph connection.
4. Review custom `DelayScheduler` implementations and `GraphRuntime::recover()` / `recoverLocked()` overrides for repeat scheduling with an unchanged due time and authority.
5. Back up, pause new work, drain every old web/Octane/Horizon/queue/scheduler process, deploy the SDK and consuming application together, run migrations and `agent-graph:doctor`, then restart all processes on the same build. Never mix 0.15 and 0.16 execution against the same runtime records.

Applications already verified on RC2 need no additional schema or runtime adaptation for stable 0.16.0. They should still verify the resolved source, restart long-lived processes in a coordinated way, and retain their RC2 reconciliation records.

## Limits that still apply

- `recover()` is explicit; AgentGraph does not add a universal scanner for stranded waits.
- Legacy 0.15.1 delay checkpoints without the required `runtime.wait` marker need explicit reconciliation.
- Due-time enforcement belongs to the asynchronous scheduler and transport. Laravel `sync` and `deferred` queues are not durable delayed transports.
- A remote effect can succeed before its task receipt is stored, and an expired lease cannot cancel work already in flight. Stable operation identities, provider idempotency where available, and reconciliation of unknown outcomes remain required.
- Synchronous work before a durable checkpoint can execute again during recovery.
- Core parent cancellation does not provide arbitrary child-tree ownership or cascade cancellation.
- AgentGraph does not promise universal exactly-once external effects, provider behavior, or fault-free production execution.
