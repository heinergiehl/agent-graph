# AgentGraph 0.18.1

This patch closes an accepted-resume recovery ordering gap in 0.18.0. After a process stopped between resume acceptance and continuation, recovery could schedule a receipt or fail a parent before noticing changed response, child-parent, child-node or graph-version bindings. The reproduced fault did not demonstrate a successful foreign external effect.

## Behavior

`ResumeProtocol::assertRecoveryBindings` validates durable authority before `GraphRuntime` schedules recovery, claims a node receipt or commits a superstep. It checks the resolved response, run/checkpoint identity and version, complete Send schedule, resume hash, receipt state and recursive child bindings. A rejected recovery leaves persistence unchanged. Historical child waits and responses remain checked after child progress; a valid completed receipt can still commit the child's next wait.

An unchanged resume can be redelivered after its acceptance marker has moved into a node receipt. Nested child identity is retained, and an expired parent receipt can continue an already accepted child without creating a new child or repeating completed work. Live receipt leases still prevent replacement execution.

No new table, migration, public method or persistence adapter contract is introduced. The protected `drive` method accepts an optional graph registry argument; custom overrides must forward it. Inconsistent legacy evidence is rejected for reconciliation instead of allowing an accepted receipt to override a contradictory checkpoint.

```bash
composer show heiner/agent-graph --format=json

```

Align exact package and deployment pins before refreshing the consuming application's lock. Verify the resolved source reference against the release commit, and restart all graph-executing processes on that dependency set. Laravel AI stays on `^0.11.2`.

After the consuming chatbot's `AgentGraphStructuredConcurrencyAcceptedResumeRecoveryTest` and `AgentGraphProjectionStateAuthorityTest` pass with SDK validation active, remove only the duplicate `StructuredConcurrencyGraphRuntime::assertRecoveryBindings` guard and its calls. SDK receipt redelivery also supersedes `matchesAcceptedNodeResume`, subject to those integration tests. Keep the application's direct-child authorization, execution context, structured ancestry policy and terminal cancellation cascade. This SDK task does not edit or certify the consuming application's runtime or lock.

## Limits

This is persistence authority validation, not a new exactly-once external-effect guarantee. An external request whose outcome was lost still requires idempotency and reconciliation. Diagnostic events are not authorization hooks. Native tool approval resumption, unsupported parallel graph interrupts and application tenant/user authorization retain their existing contracts. No paid provider calls were made.
